# AGENTS.md

lintoko is an extensible linter for Motoko: it applies rules written as Tree-sitter
queries in TOML files to Motoko (`.mo`) source.

## Build, test, lint, format

Requires a Rust toolchain (edition 2024). Commands below are used by CI and the `justfile`.

- Build: `cargo build`
- Test: `cargo test`
- Lint: `cargo clippy --all-targets -- -D warnings` (warnings are errors)
- Format check: `cargo fmt --all --check`
- Apply formatting: `cargo fmt --all`

CI (`.github/workflows/ci.yml`) runs build, test, clippy, and the format check on every
push and PR to `main`; all four must pass. The `just` and `cargo-insta` tools are optional
conveniences documented in `DEVELOPMENT.md`.

## Snapshot tests

Tests use `insta` snapshots stored in `src/snapshots/`. When a change intentionally alters
output, review and update snapshots rather than hand-editing them:

- `INSTA_UPDATE=always cargo test` (also available as `just test-accept`)

## Layout

- `src/` — the crate (library, `lintoko` binary, and tests).
- `example-rules/` — example rule TOML files; several tests load these directly, so
  changing or removing a file here can break `cargo test`.
- `test-data.mo` — fixture Motoko file used by tests.
- `.github/workflows/release.yml` — release automation, autogenerated by `cargo-dist`.

## Conventions and gotchas

- `dist-workspace.toml` and `.github/workflows/release.yml` are generated by `cargo-dist`;
  do not hand-edit them. Regenerate via `cargo-dist` instead.
- Releases are cut by pushing a git tag matching `X.Y.Z` (see `DEVELOPMENT.md`); the version
  in `Cargo.toml`, `CHANGELOG.md`, and `Cargo.lock` must be updated together first.
- `tree-sitter-motoko` is pinned to a specific git revision in `Cargo.toml`.
- `/target` is git-ignored.
- Rules are TOML files with `name`, `description`, and a Tree-sitter `query` field; pass rule
  directories to the binary with `-r`, and apply auto-fixes with `--fix`.
